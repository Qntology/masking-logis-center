# PRD: AI Commerce Automation Assistant (Commerce Automation Agent)

## 1. 개요
본 프로젝트는 일반 판매자(비개발자)가 복잡한 커머스 웹페이지 및 물류/무역 시스템의 상태를 AI와의 대화만으로 안전하게 처리할 수 있는 '무한 컨텍스트 기반 지능형 장부 에이전트'를 구축하는 것입니다.

## 2. 목표
- 판매자가 코딩 없이 브라우저 데이터를 자동 취합/관리하도록 지원.
- AI 컨텍스트 오염 방지 및 비용 최적화 (Git-like 데이터 관리).
- 비개발자 친화적 UX/UI (Zero-Config, Human-in-the-Loop, 상태 동기화 제어).

## 3. 핵심 기술 아키텍처
### 3.1. 자동화 엔진
- **엔진:** `chromiumoxide` (CDP 기반 브라우저 제어).
- **UI Interaction:** 브라우저 내 오버레이 UI 주입 (Toggle 버튼 클릭 시 AI 관리 패널 노출).

### 3.2. 상태 동기화 및 데이터 관리 (Two-Tier Sync)
- **Tier 1 (Temporary/Staging):** `Dexie DB`를 사용하여 웹페이지에서 감지된 실시간 DOM 변화를 임시 저장.
- **Tier 2 (Official Repository):** `LanceDB`를 사용하여 사용자가 검증하고 'Push'한 확정 상태를 Git-like 버전 관리 시스템으로 저장.
- **Unified Schema:**
    | 필드명 | 타입 | 설명 |
    | :--- | :--- | :--- |
    | `id` | String | SHA256(URL), 데이터의 영구적 고유 ID |
    | `host` | String | 호스트 도메인 (e.g., sell.smartstore.naver.com) |
    | `url` | String | 전체 URL |
    | `domain` | Enum | COMMERCE, LOGISTICS, TRADE |
    | `context` | String | 정제된 데이터 본문 (YAML) |
    | `status` | Enum | DRAFT, READY_TO_PUSH, COMMITTED |
    | `track` | Enum | MAIN, SUB |
    | `version` | Integer | 수정 횟수 (Git 커밋 커밋 카운터) |
    | `created_at` | Timestamp | 생성 시점 |
    | `updated_at` | Timestamp | 최종 변경 시점 |

### 3.3. 데이터 정제 및 추출 (DOM-to-YAML)
- **DOM Cleaning:** HTML에서 불필요 태그 제거 및 속성(attributes) 제거.
- **Normalization:** 순수 텍스트 계층 구조를 **YAML 포맷**으로 변환하여 토큰 효율성 극대화.
- **Unique Identifier:** 페이지 URL을 SHA256으로 해싱하여 `page_id` 생성. 이를 통해 데이터 지문(Fingerprint) 식별 및 Git-like 버저닝 구현.

## 4. Architecture vs. Implementation (Reconciliation)
- **Branching/Pruning:** Implemented in `src-tauri/src/lib.rs` using asynchronous `Command` execution and state locking.
- **Two-Tier Storage:** `Dexie DB` for temporary staging, `LanceDB` for schema-validated, version-controlled storage.
- **Vector Search (Embeddings):** LanceDB integration with `embeddinggemma-300m` via custom EmbeddingFunction for semantic search.
- **FTS (N-gram):** LanceDB `create_fts_index` configured with N-gram tokenization (n=3) for multi-lingual full-text search.
- **Git-style Diff:** Implemented using `similar` and exposed via IPC `calculate_state_diff`.

## 5. 사용자 경험 (UX) 전략
- **State Transparency:** UI에서 '임시 상태(DRAFT)'와 '확정 상태(COMMITTED)'를 명확히 구분.
- **Commit Flow:** 채팅 UI 내에서 변경 내용을 체크박스로 선택하고 [Push]하여 LanceDB에 동기화.
- **Audit Trail:** 모든 Push(Commit)는 이력으로 관리되며 필요시 롤백 가능.

## 6. 향후 로드맵
- Phase 1: Chromiumoxide 연동 및 오버레이 UI 구현 (Dexie 기반 데이터 수집 시작).
- Phase 2: DOM-to-YAML 로직 및 SHA256 `page_id` 구현.
- Phase 3: LanceDB 동기화 로직(Push 기능) 및 Git-like Diff UI 구현.
- Phase 4: 이미지 인식(멀티모달) 기반 송장-주문 매칭 기능.
